# FIRE 3D — 火災現場逆向評估系統

**英文正式名稱：Forensic Incident Reconstruction & Evaluation System**  
**縮寫／顯示名稱：FIRE 3D**  
**中文正式名稱：火災現場逆向評估系統**  
**目前版本：v0.1（室內配置階段；2026-11-15，新增直接拖曳隔間牆）**

> 本專案的主要目標，是讓使用者從具有物理模擬依據的火災後現場出發，建立起火位置與原因的不同假說，再以前向計算、證據標記及多情境比較輔助火災調查訓練。**真正的逆向調查功能將在正向模型完成並驗證後才開發**。目前 v0.1 僅供室內建模與資料結構測試，不包含火災模擬。

## 1. 專案方向與設計原則

1. **先正向、後逆向：** 先完成房間、家具、材料、燃燒、通風、燒損生成及時間資料紀錄；再利用正向結果建立預先計算的災後案例與逆向調查流程。
2. **兩種模擬並存：** 既有正向案例可倒序重播；使用者任意修改家具、隔間、材料或火源後，重新計算新的正向結果。不得將舊結果當作新配置的物理結果。
3. **簡潔介面：** 3D 場景為主、初始約 45 度視角、可旋轉／平移／放大；操作透過可移動、可調整大小與可收合的浮動視窗完成。明亮色系呈現災前公寓；未來災後案例可有獨立的火害視覺圖層。
4. **資料可追溯：** 物件和房間有獨立 ID，保存幾何、材質、門窗及設定。燃燒數值需具備實驗來源與適用範圍，不用未經證實的數字冒充實測值。
5. **科學與鑑識界線：** 預存計算歷程的時間倒轉 **不等於** 由真實火場唯一反推出起火點。真實案件只能提出候選情境，並依現場證據及模型不確定度比較。

### 特別注意：風險數值的分層

- **蔓延風險指數**（v0.3）：著重特定起火情境下家具之間的引燃、熱釋放率成長與房間延燒時間。
- **逃生困難度**：不能直接用蔓延分數替代；需待 v0.4 之後將熱、煙、可視距離、毒性與路徑等因素納入，才可能參考 ASET／RSET 的消防工程評估方式。
- 兩者均不能直接聲稱符合特定建築消防法規；須有正式法規核對與模型驗證程序。

## 3. v0.1 介面與四組範本

目前提供 4 組可直接編輯的教學範本，主要採公寓常見的**客餐廚／私人臥室分區、門窗與走道連通、櫃子正面朝向可使用的一側**等原則重新繪製。這些範本是新建的簡化幾何模型，不是任何建商平面圖的直接複製。

| 範本 | 參考規劃方向 | 模型尺寸 | 配置 |
|---|---|---|---|
| A：雙房中央走道 | 70–80㎡ 雙房平面圖的中央通道模式 | 10.3 × 7.7 m（約 79㎡） | 客餐廳、獨立廚房、走道、2 臥、1 衛 |
| B：高家具密度雙房 | 以 A 的空間格局增加可燃物與陳設變因 | 10.3 × 7.7 m（約 79㎡） | 延用 A 的格局，增加書櫃、織物家具 |
| C：簡約一房公寓 | 開放式起居／廚房、一房一衛的小坪數公寓 | 8.9 × 7.3 m（約 65㎡） | 客餐廳、開放式廚房、1 臥、1 衛 |
| D：雙房開放式餐廚 | 開放式廚房與客餐廳相連、臥室分區模式 | 10.1 × 7.7 m（約 78㎡） | 客餐廚、2 臥、1 衛 |

**家具使用方向修正：** 書櫃、衣櫃、冰箱、電視及廚櫃的正面以模型局部 +Z 定義；範本已按可使用方向配置。選取這類物件時，場景有青綠色正面標記，浮窗可查看面向及與房間邊界的估計距離，並按「正面自動朝向房內」。手動新增櫃子也會靠牆、正面朝向室內。這個距離暫不包含其他家具遮擋或門片實際開啟半徑。

### 直接拖曳隔間牆（v0.1 本次修訂）

1. 點擊左側／手機底部的 **「隔間與尺寸」** 圖示，進入隔牆拖曳模式。3D 室內會出現青綠色的隔牆線與中央抓取點。
2. 使用滑鼠／單指按住青綠色隔牆線或中央控制點，**沿牆面的垂直方向**移動。可先按右下角「俯視平面圖」再拖曳，位置更容易判讀。拖曳時不會改變相機角度。
3. 牆壁移動時兩側隔間面積及尺寸會即時重新計算；畫面小標籤顯示兩側隔間的面積（㎡）。選取牆壁後，浮窗還可輸入座標或每次 ±0.25 m 微調。
4. **避免極端變形：** 拖曳時保證分割樹內的所有隔間各方向至少約 1.2 m，並維持建築外框不變。這是軟體編輯下限，**不是法規規定的走道／逃生淨寬標準**。
5. **門窗跟隨牆面變更：** 原屬牆壁仍使用同一個牆段 ID；若因其他牆移動而影響所在牆段長度，調整門窗相對座標，盡量保留原本的沿牆實際位置（必要時向牆段範圍內限制）。
6. **家具不會自動位移：** 若新牆位置與家具衝突、導致家具跨越房間邊界或被移入另一隔間，家具會保留原座標並出現橘色框線提醒；使用者再切回「選取與編輯」模式調整。
7. 牆面修改可使用復原，會保存至既有的瀏覽器自動儲存和 JSON；**資料 schema 不變**（`fire3d-interior-v0.1`），可讀取先前 v0.1 存檔。手機操作時，浮動視窗預設縮小，避免遮住可拖曳的牆面；點擊浮窗的縮小／展開按鈕即可打開詳細參數。

隔間牆不能在一般選取模式任意拖曳，避免使用者只是想轉動 3D 視角卻改變建築配置。支援的是正交、矩形遞迴隔間，非任意斜牆、非施工圖 BIM 模型。

**目前限制：** v0.1 的隔間仍為矩形遞迴分割，暫不支援任意斜牆、任意形狀的洞口或專業施工細部。窗、門目前有幾何和開關狀態，但尚未參與通風物理計算。家具模型與材質供視覺編輯；**不代表已經具有可靠的燃燒係數**。範本面積為概略幾何面積，未以建築法規計算室內淨面積或公設。

## 4. 檔案命名與部署

為遵循專案名稱，**後續的交付檔案統一以 `fire3d` 作為名稱結尾識別**：

- 單檔測試版：`v0.1_fire3d.html`、`v0.2_fire3d.html` 等。
- GitHub 部署包：`v0.1_fire3d.zip`，ZIP 內放 `index.html` 和 `README.md`。
- 使用者匯出的配置：`v0.1_fire3d_<timestamp>.json`。
- `index.html` 是 GitHub Pages 的網站首頁慣例；雖然部署時名稱為 `index.html`，其內容對應 FIRE 3D 專案，不改變對外交付的版本識別。

### GitHub Pages 操作

1. 下載 `v0.1_fire3d.zip`，解壓縮後取得 `index.html` 與 `README.md`。
2. 將這兩個檔案放入 GitHub 儲存庫 `eduGame/games/fire3d/`。
3. 待 Pages 部署完成後，開啟 `https://chyijiunn.github.io/eduGame/games/fire3d/`。
4. 本版 HTML 不依賴 CDN 3D 套件；單獨開啟 `v0.1_fire3d.html` 也能操作，但本機模式無法載入 GitHub 網站上的 GA4 共用設定。

### GA4

沿用既有的共用載入方式，位於 `<head>`：

```html
<script src="/eduGame/ga4.js" defer></script>
```

此檔案需由原 `eduGame` 網站正確提供；其成功載入和 GA4 是否收到事件需於上線後實際檢查。`v0.1` 不會自行新增新的 GA Measurement ID。

### JSON 與瀏覽器儲存

- 新版本 schema：`fire3d-interior-v0.1`。
- 新版自動儲存 key：`fire3d-v0.1-autosave`。
- 舊版 `fire-interior-v0.1` 配置 **可以透過「匯入 JSON」載入**，載入後寫成新 schema；不覆蓋舊版瀏覽器儲存資料。
- 跨瀏覽器與跨裝置請用 JSON 匯出／匯入，勿僅依賴 localStorage。

## 6. 法律、使用及安全限制

本系統現階段供教育、訓練、消防工程研究及模擬方法開發。未經正式校正與專業審查，不得將其火災蔓延、風險指數或逆向推演結果當作**確定的事故起因、法定消防安全證明或正式鑑定結論**。若未來納入實際事故的照片、掃描或調查資料，應依案件權限與適用法律處理個資、現場資料、證據版本及異動紀錄。

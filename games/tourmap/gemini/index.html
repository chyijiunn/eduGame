布拉格 10日遊地圖 - 版本演進

從最初的靜態直線原型，一路升級到支援 OSRM API 分段行人演算法的完整歷程。點擊縮圖或按鈕即可預覽該版本。

🗺️ 點擊預覽 v0.1
Version 0.1

基礎原型與 UI 框架

第一個概念驗證版。建立了基本的 HTML/CSS 介面與 Leaflet.js 地圖初始化，採用點擊切換天數的單選模式。
💻 程式碼亮點：
使用硬編碼的 Array 儲存 GPS 座標，透過 `L.polyline()` 將各點以「直線」直接相連。切換時透過 `map.removeLayer()` 清除上一條路線。
開啟 proha v0.1.html
🗺️ 點擊預覽 v0.12
Version 0.12

標記擴充與 Bug 修正

修正了在 JavaScript 中呼叫 CSS 變數導致地圖無法載入的錯誤，並增加了每天「圓形回程路線」的點位與圖標。
💻 程式碼亮點：
修正 `color: var(--primary-color)` Bug 為 Hex 色碼。新增 `L.marker().bindPopup()` 迴圈，動態將每天陣列中的地標轉化為地圖上的實體標記點。
開啟 proha v0.12.html
🗺️ 點擊預覽 v0.13
Version 0.13

OSRM API 真實軌跡導入

重大架構升級！捨棄假直線，改為串接第三方導航引擎畫出真實道路。UI 改為可「多選重疊顯示」以比對路線。
💻 程式碼亮點：
引入 `fetch()` 異步請求 OSRM API。使用 `L.geoJSON()` 解析回傳的真實經緯度軌跡。將單一變數管理改為 `activeRoutes{}` 物件，實現多圖層共存管理。
開啟 proha v0.13.html
🗺️ 點擊預覽 v0.14
Version 0.14

純步行模式與虛線視覺

專注於旅遊步行體驗，強制引擎只抓取行人專用道（排除汽車路徑），並將地圖視覺改為代表步行的虛線。
💻 程式碼亮點：
將 API URL 的 profile 參數改為 `/v1/foot/`。在 `L.geoJSON` 中加入 `dashArray: '8, 8'` 繪製虛線。加入 `try...catch` 降級機制，API 失效時畫回直線防呆。
開啟 proha v0.14.html
🗺️ 點擊預覽 v0.15
Version 0.15

演算法防呆與距離計算

為解決 OSRM 引擎「禁止原地迴轉」導致的巨大繞路問題，加入了數學計算做為防護網，過濾不合理的導航。
💻 程式碼亮點：
寫入 `getDistance()` 半正矢公式 (Haversine formula)。當 API 回傳距離 > 數學直線距離的 2.5 倍時，觸發防呆機制捨棄軌跡。API 附加 `continue_straight=false`。
開啟 proha v0.15.html
🗺️ 點擊預覽 v0.16
Version 0.16

分段尋路(最終完美版)

徹底解決連續景點導航的繞路 Bug。不再使用防呆裁切，而是改變請求邏輯，完美縫合每一段真實的巷弄步行軌跡。
💻 程式碼亮點：
捨棄一次傳送 10 個點。改寫為 `Segment-by-Segment` 迴圈演算法，兩兩座標一組呼叫 API，最後將取得的 `coordinates` 陣列重新組合成單一的 `LineString` GeoJSON 物件。
開啟 proha v0.16.html
